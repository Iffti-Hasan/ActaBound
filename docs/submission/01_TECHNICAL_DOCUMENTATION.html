1. Executive Summary & Problem Formulation

The integration of generative artificial intelligence into decentralized finance creates a fundamental paradigm shift: transitioning algorithms from passive informational assistants into autonomous economic participants. However, granting Large Language Models direct signing authority exposes capital to four systemic failure modes:

  • Adversarial Prompt Injection (OWASP LLM01): Malicious prompts disguised as transaction memos manipulate the LLM into altering recipients or bypassing security controls.
  • Floating-Point Accounting Drift (IEEE 754): JavaScript floating-point arithmetic introduces fractional errors, creating exploit windows for balance drainage.
  • Time-of-Check to Time-of-Use (TOCTOU) Exploits: Discrepancies between approved plan parameters and mempool calldata.
  • Private Key Leakage: Placing private keys in the LLM's operational context creates unacceptable extraction vulnerabilities.
The ActaBound Paradigm — Bounded Authority: ActaBound completely decouples probabilistic natural-language planning from deterministic execution. The AI agent proposes structured plans but possesses zero signing keys. A pure BigInt deterministic policy engine evaluates boundaries against an immutable mandate, simulates outcomes via the Financial Twin, and permits signing only within isolated hardware/KMS enclaves.

3. Core Algorithm Description & Invariants

3.1 Exact BigInt Currency Normalization

To eliminate floating-point drift, all token balances are mapped to exact integer units:

export function parseTokenUnits(amountStr: string, decimals: number = 6): bigint {
  const clean = amountStr.trim().replace(/,/g, '');
  const parts = clean.split('.');
  const wholePart = parts[0] || '0';
  const fracPart = (parts[1] || '').slice(0, decimals).padEnd(decimals, '0');
  const wholeUnits = BigInt(wholePart) * (10n ** BigInt(decimals));
  const fracUnits = BigInt(fracPart);
  return wholeUnits + fracUnits;
}

3.2 Inviolable Protected Reserve Invariant

Let \(B_t\) be the current token balance, \(R\) be the protected reserve floor, and \(\Delta x\) be the proposed spend. The transaction is valid if and only if:

B_{t+1} = B_t - \Delta x \ge R \quad \Longleftrightarrow \quad \Delta x \le B_t - R

If \(\Delta x > B_t - R\), the policy engine halts fail-closed with code RESERVE_BREACH.

3.3 Cryptographic Evidence Block Hash Chaining

Every audit block is linked recursively using SHA-256:

Block_n Hash = SHA-256( PrevHash || SHA-256(Payload_n) || SequenceNumber || Timestamp )
